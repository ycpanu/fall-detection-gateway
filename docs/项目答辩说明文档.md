## 1. 项目概述

本项目是一个**基于边缘计算的摔倒检测系统**，运行在 Rockchip NPU（RK3566）开发板上。系统通过 USB 摄像头实时采集画面，利用 **YOLOv8n-Pose 人体骨骼关键点模型**在 NPU 上做硬件加速推理，提取人体的 17 个骨骼关键点，再由**规则引擎**依据「身体轴线角度 + 髋部下坠速度 + 时序状态机」综合判断是否发生摔倒。

一旦确认摔倒，系统会：

1. **本地报警** —— 通过 Sysfs 操控 GPIO 引脚驱动蜂鸣器；
2. **现场取证** —— 从环形缓存中异步合成摔倒前 N 秒的短视频（MP4）；
3. **云端上报** —— 通过 MQTT 将报警事件 JSON 推送到云端；
4. **断网容灾** —— 网络中断时报警数据自动落盘 SQLite，网络恢复后补传（Store-and-Forward）。

系统采用**多线程 + 线程安全队列**解耦的设计，将「采集 → 推理 → 判定 → 报警」串成一条低延迟、可容错的流水线，最终落地为一个可直接部署在边缘设备的可执行程序。

## 2. 项目背景与意义

### 2.1 社会背景

人口老龄化加剧，独居老人、养老院、医院病房等场景中的跌倒（摔倒）是导致老年人意外伤害甚至死亡的主要原因之一。跌倒后若不能及时发现和救助，会造成严重后果。传统的穿戴式设备（手环、报警按钮）存在老人不愿佩戴、忘记充电、跌倒后无法主动触发等问题。

### 2.2 技术背景

- **摄像头视觉方案**无需老人配合，无感监测；
- **边缘计算**：将 AI 推理下沉到设备端，数据无需上传云端即可完成分析，具备低延迟、保护隐私、弱网可用等优势；
- **NPU 加速**：Rockchip RK3566 内置 NPU（0.8 TOPS），可在低功耗下运行神经网络推理，适合长期无人值守的嵌入式场景。

### 2.3 项目意义

- 实现 **7×24 小时无感、自动、实时的摔倒检测**；
- 边缘端完成核心判断，**数据不出本地**，保护隐私；
- 报警链路完整：**本地声光报警 + 现场视频取证 + 云端通知家属**；
- 具备**弱网/断网容灾能力**，保障关键报警不丢失。

## 5. 核心模块详细设计

### 5.1 ThreadSafeQueue —— 线程安全队列

**文件**：`include/fall-detection/concurrency/ThreadSafeQueue.hpp`

采用 C++ 模板实现，可复用为图像队列（`cv::Mat`）和报警队列（`AlertEvent`）。核心设计：

- **互斥锁 `std::mutex` + 条件变量 `std::condition_variable`** 保证并发安全；
- **`push`**：队满时自动丢弃最旧元素（防止采集线程跑太快撑爆内存），并使用 `std::move` 转移所有权，避免大图像拷贝；
- **`wait_and_pop`**：阻塞式获取，队列空时线程休眠（**零 CPU 轮询**），直到 `notify_one` 唤醒；
- **`wait_for_and_pop`**：带超时的阻塞获取，用于主循环和报警线程周期性检查退出标志，实现优雅退出；
- 使用 `std::lock_guard` / `std::unique_lock`（RAII 智能锁），异常时自动解锁，杜绝死锁。

### 5.2 CameraStreamer —— 摄像头采集

**文件**：`src/vision/CameraStreamer.cpp` + `.hpp`

- **双模式**：构造函数重载支持 **USB 摄像头**（`/dev/video0`，强制 `CAP_V4L2`）与 **本地视频文件**（用于回归测试）；
- **独立采集线程**：在 `captureLoop()` 中抓帧，避免后端 AI 推理/网络波动阻塞采集；
- **MJPG 格式锁定**：`capture_.set(CAP_PROP_FOURCC, 'MJPG')`，解决部分 V4L2 驱动的抓图死锁问题；
- **视频循环播放**：视频文件播到末尾自动重置帧指针，实现循环回归测试；
- **限帧**：通过动态 `sleep` 将采集速率限制在约 30 FPS；
- 抓到的每一帧同时 `push` 到帧队列和视频缓存器。

### 5.3 VideoCacher —— 短视频异步缓存

**文件**：`src/vision/VideoCacher.cpp` + `.hpp`

- **环形缓冲（Ring Buffer）**：用 `std::deque` 维护固定长度滑动窗口（默认 90 帧，约 3 秒），新帧入队、旧帧出队；
- **异步合成**：报警触发时，先在锁内快速**拷贝快照**（最小化锁占用），再启动独立线程用 `cv::VideoWriter` 编码为 MP4，**不阻塞主线程**；
- **编码器容错**：优先 `H.264(avc1)`，若精简编译的 OpenCV 无 libx264 则**回退 `MPEG-4(mp4v)`**；
- **偶数宽高修正**：H.264/MPEG-4 要求宽高为偶数，奇数会被向下取整，避免写出无法播放的损坏文件；
- **生命周期保障**：后台编码线程句柄存于成员 `writerThreads_`，析构时统一 `join`，确保退出前视频写完（避免缺 `moov` 头无法播放）。

### 5.4 RKNNInferencer —— NPU 硬件推理（系统「大脑」）

**文件**：`src/vision/RKNNInferencer.cpp` + `.hpp`

负责加载 `.rknn` 模型、执行 NPU 推理，并完成 17 骨骼点解码与 NMS。

**初始化流程 `init()`**：

1. 读取 `.rknn` 模型文件到内存；
2. `rknn_init()` 初始化 NPU 上下文；
3. `rknn_query()` 查询输入/输出张量属性（数量、维度、元素个数）。

**推理流程 `detect()`**：

1. **预处理**：BGR→RGB，再 **letterbox 等比缩放**（保持宽高比，灰边 114 填充），避免画面拉伸变形；
2. **输入**：将图像数据指针直接交给 NPU（`RKNN_TENSOR_UINT8` / `NHWC`）；
3. **推理**：`rknn_inputs_set` → `rknn_run` 一键硬件计算；
4. **输出解析**：`want_float=1` 强制 NPU 将 INT8 结果反量化为 float32；
5. **后处理（解码 + NMS）**：

   - YOLOv8-Pose 输出布局为每个锚框 56 个属性：
     `[0..3] 边框 cx,cy,w,h`、`[4] 类别置信度(person)`、`[5..55] 17 个关键点(x,y,conf)`；
   - 过滤置信度低于阈值的锚框；
   - 边框与关键点坐标**逆映射回原图**（先减 letterbox 灰边偏移 `padW/padH`，再除以缩放比例 `scale`）；
   - **NMS（非极大值抑制）**：按置信度降序排序，逐框计算 IoU，剔除重叠的重影框。

6. **内存释放**：`rknn_outputs_release` 释放 NPU 输出内存，防止泄漏。

### 5.5 FallRuleEngine —— 摔倒规则引擎

**文件**：`src/vision/FallRuleEngine.cpp` + `.hpp`

将「静态关键点」转化为「动态摔倒判定」，详见 [第 6 节](#6-摔倒判定算法详解)。

### 5.6 MqttClient —— 云通信

**文件**：`src/network/MqttClient.cpp` + `.hpp`

- 使用 **Paho MQTT C++ 异步客户端**（`mqtt::async_client`）；
- **连接配置**：`clean_session(true)`、心跳保活 `keep_alive_interval`（默认 20s，适应弱网）、`set_automatic_reconnect(1, 10)` **断网自动重连**；
- **发布**：将 `AlertEvent` 用 nlohmann/json 组装为标准 JSON，以 **QoS 1（至少到达一次）** 发布：
  ```json
  {
    "device_id": "OrangePi_Gateway_001",
    "event_type": "FALL_DETECTED",
    "timestamp": 1720000000000,
    "data": { "trigger_x": 320, "trigger_y": 240, "status": "CRITICAL" }
  }
  ```

### 5.7 LocalDatabase —— 本地容灾（Store-and-Forward）

**文件**：`src/utils/LocalDatabase.cpp` + `.hpp`

- 基于 SQLite3，`alerts` 表结构：`id`（自增主键）、`timestamp`、`trigger_x`、`trigger_y`、`status`（`pending`/`uploaded`）；
- **`saveAlert`**：断网时把报警落盘，`status` 记为 `pending`；
- **`getPendingAlerts`**：查询所有 `pending` 记录，供网络恢复后补传；
- **`markAsUploaded`**：补传成功后把对应记录标记为 `uploaded`；
- **业务逻辑（在 main.cpp 报警线程中）**：网络在线时，先遍历补传所有历史 `pending` 事件，再发布当前最新报警；发布意外失败也落盘保存，实现**报警事件不丢失**。

### 5.8 BuzzerController —— 蜂鸣器

**文件**：`src/hardware/BuzzerController.cpp` + `.hpp`

- 通过 Linux **Sysfs** 操控 GPIO：`export` 导出引脚 → 设置 `direction=out` → 写 `value` 控制高低电平；
- **异步报警**：`triggerAlarm` 启动独立 `detach` 线程，拉高电平 → 睡眠 `durationMs` → 拉低电平，**不阻塞报警处理主流程**；
- 析构时释放引脚（写 0 并 `unexport`）。

### 5.9 ConfigManager —— 全局配置（单例）

**文件**：`src/utils/ConfigManager.cpp` + `.hpp`

- **单例模式**（禁用拷贝），启动时加载 `configs/config.json`；
- **所有 getter 内置默认值**：配置文件缺失、解析失败或字段缺失时，系统按默认值继续运行，**不会启动失败**；
- 提供**类型安全的命名 getter**（如 `getBuzzerGpioPin()`）与**通用点号取值接口**（如 `getInt("vision.frame_queue_size", 3)`）；
- `find()` 按 `.` 拆分 key 逐级下钻 JSON 节点，未找到返回 `nullptr`。

### 5.10 SysLogger —— 异步日志（单例）

**文件**：`src/utils/SysLogger.cpp` + `.hpp`

- 基于 **spdlog 异步日志器**，独立后台线程写磁盘（线程池队列 8192、1 线程），**写日志不阻塞 AI 推理主线程**；
- **双输出**：彩色控制台 + 滚动文件（单文件 5MB、最多保留 3 个，防止 SD 卡被日志占满）；
- **`flush_on(error)` 容灾**：遇到 ERROR 级别日志立即强制刷盘，防止程序段错误死机时关键现场日志丢失；
- 提供 `LOG_TRACE` ~ `LOG_CRITICAL` 宏，带源码文件与行号定位。

## 6. 摔倒判定算法详解

摔倒判定是系统的核心逻辑，位于 `FallRuleEngine::processFrame()`，采用 **「几何特征 + 运动特征 + 时序状态机」** 三层融合策略，有效区分「摔倒」与「坐下/弯腰/蹲下」等易混淆动作。

### 6.1 COCO 17 关键点

采用 YOLOv8-Pose 标准 COCO 关键点索引，本算法只用其中 4 个：

| 索引 | 名称 | 用途 |
| --- | --- | --- |
| 5 | 左肩 L_SHOULDER | 计算肩中点 |
| 6 | 右肩 R_SHOULDER | 计算肩中点 |
| 11 | 左髋 L_HIP | 计算髋中点 |
| 12 | 右髋 R_HIP | 计算髋中点 |

### 6.2 特征一：身体轴线角度（几何特征）

取肩中点 `(shoulderX, shoulderY)` 与髋中点 `(hipX, hipY)`（两侧都可见取平均，否则取可见侧），计算身体轴线与**垂直方向**的夹角：

```
dx = hipX - shoulderX
dy = hipY - shoulderY
angle = atan2(|dx|, |dy|) * 180 / π
```

- 站立时身体接近垂直，`angle` 很小；
- 躺倒时身体接近水平，`angle` 接近 90°；
- 当 `angle > fall_angle_threshold`（默认 60°）时，判定为「疑似躺倒」。

> 该特征能过滤「弯腰捡东西」（躯干倾斜但未到躺倒程度）。

### 6.3 特征二：髋部下坠速度（运动特征）

利用相邻两帧的髋部 Y 坐标变化率刻画下坠速度：

```
velocityY = (hipY - previousHipY) / dt
```

- 图像坐标系 **y 轴向下**，摔倒时髋部快速下坠，`velocityY` 为正且数值大；
- 当 `velocityY > fall_velocity_threshold`（默认 400 px/s）时，标记「快速下坠事件」进入时序窗口。

> 该特征能区分「摔倒」（快速下坠）与「缓慢坐下/躺下」（速度慢）。

### 6.4 特征三：时序状态机（防抖 + 双路径）

引擎维护多个状态变量：

| 状态变量 | 含义 |
| --- | --- |
| `lieConfirmCount_` | 躺倒连续帧计数（防抖） |
| `fallEventPending_` | 快速下坠事件是否仍在时序窗口内 |
| `fallEventFrames_` | 下坠事件发生后经过的帧数 |
| `hasPreviousTarget_` / `previousHipY_` / `lastTime_` | 上一帧目标状态（算速度用） |

**报警判定（双路径 OR）**：

- **路径 A —— 动态摔倒**：`快速下坠事件仍在窗口内` 且 `连续躺倒 ≥ confirm_frames_threshold`（默认 5 帧）；
- **路径 B —— 静态摔倒（兜底）**：`连续躺倒 ≥ static_lie_threshold`（默认 30 帧，约 1 秒）。

> 路径 A 捕捉「明显下坠」的典型摔倒；路径 B 兜底「可能没抓到下坠瞬间」的缓慢摔倒或画面中已躺倒的情况，二者结合提高召回率。

### 6.5 状态重置机制

- 当前帧**未检测到人**、**关键点不足 17 个**、**肩/髋不可见**（置信度低于阈值）时，均调用 `resetState()` 清空状态；
- 目标**姿态恢复**（`angle` 回到阈值内）时，`lieConfirmCount_` 归零并解除报警；
- 触发报警后立即 `resetState()`，**避免同一事件重复报警**。

### 6.6 判定流程图

```
        ┌──────────────┐
        │  输入一帧结果  │
        └──────┬───────┘
               ▼
        ┌──────────────┐   否

        └──────┬───────┘
```

## 7. 数据流与线程模型

### 7.1 数据流

```
CameraStreamer ──▶ frameQueue ──▶ RKNNInferencer ──▶ FallRuleEngine ──▶ alertQueue ──▶ MqttClient / LocalDatabase
```

### 7.2 线程模型（3 个主线程 + 若干辅助线程）

| 线程 | 位置 | 职责 |
| --- | --- | --- |
| **采集线程** | `CameraStreamer::captureLoop()` | 持续抓帧，投递到帧队列与视频缓存 |
| **主流水线线程** | `main()` 主循环 | 从帧队列取帧 → NPU 推理 → 规则判定 → 投递报警队列 |
| **报警响应线程** | `main()` 中 `alertThread` | 从报警队列取事件 → 蜂鸣器 + 补传 + MQTT 发布 |
| **视频编码线程** | `VideoCacher` 后台 | 异步合成 MP4 短视频 |
| **蜂鸣器线程** | `BuzzerController` 内部 `detach` | 异步蜂鸣，不阻塞 |
| **日志线程** | spdlog 线程池 | 异步写日志文件 |

### 7.3 优雅退出机制

- 全局标志 `volatile std::sig_atomic_t g_running`，`SIGINT/SIGTERM` 信号处理器**只做标志位翻转**（不加锁、不分配内存，保证信号安全）；
- 各线程循环通过带超时的 `wait_for_and_pop` 周期性检查 `g_running`，安全退出；
- 主线程退出前 `stop()` 采集线程、`join()` 报警线程、`disconnect()` MQTT，释放所有资源。

## 9. 关键技术难点与解决方案

### 难点 1：采集与推理速率不匹配，内存易被挤爆

**方案**：引入**有界线程安全队列**（`ThreadSafeQueue`），队满时丢弃最旧帧；配合 `std::move` 转移图像内存所有权，避免大图深拷贝，控制内存占用与采集节奏。

### 难点 2：V4L2 摄像头抓图死锁 / 画面拉伸

**方案**：强制指定 `CAP_V4L2` 驱动并锁定 MJPG 格式规避死锁；模型侧通过 **letterbox 等比缩放 + 灰边填充**保持宽高比，避免画面拉伸变形，同时保证模型输入尺寸一致。

### 难点 3：NPU 输出解析复杂（锚框解码 + NMS）

**方案**：根据 YOLOv8-Pose 输出布局（每个锚框 56 属性），实现**边框/关键点坐标逆映射**（减 letterbox 偏移、除缩放比例）与 **NMS + IoU** 去重，将 NPU 原始张量解析为结构化 `DetectResult`。

### 难点 4：摔倒与「坐下/弯腰/蹲下」易混淆

**方案**：采用**「角度 + 速度 + 时序状态机」多特征融合**，几何特征过滤弯腰，运动特征过滤缓慢坐下，时序防抖过滤瞬时抖动，双路径（动态+静态）兼顾召回率与鲁棒性。

### 难点 5：弱网/断网导致报警丢失

**方案**：**Store-and-Forward 容灾**——报警先经 `isConnected()` 探针判断，在线则补传历史积压再发当前；离线或发送失败则落盘 SQLite，网络恢复后自动补传并标记 `uploaded`，保证**报警事件不丢失**。

### 难点 6：短视频合成阻塞主线程 / 写出损坏文件

**方案**：**环形缓存 + 快照拷贝 + 后台异步编码**，锁内只做快速快照；编码器 H.264 回退 MPEG-4 容错；宽高向下取偶避免写坏文件；析构统一 `join` 后台线程，避免缺 `moov` 头无法播放。

### 难点 7：长期无人值守的设备稳定性

**方案**：信号驱动的**优雅退出**；spdlog **异步日志**不阻塞主流程；滚动日志防 SD 卡写满；`flush_on(error)` 保证死机前关键日志落盘；析构释放 NPU 上下文、摄像头、数据库、MQTT 连接。

### 难点 8：跨平台交叉编译依赖管理

**方案**：`aarch64-toolchain.cmake` 指定交叉编译器与 sysroot；`fmt`/`spdlog` 通过 `FetchContent` 源码拉取编译，规避 sysroot 缺 `.so` 问题；`--allow-shlib-undefined` 允许运行期由设备系统库解析符号。

## 14. 项目亮点总结

1. **软硬件协同的边缘 AI 方案**：YOLOv8n-Pose + Rockchip NPU 硬件加速，低功耗、低延迟、本地推理保护隐私；
2. **多线程流水线架构**：线程安全队列解耦「采集—推理—判定—报警」，采集不卡顿、推理不阻塞；
3. **多特征融合的摔倒判定**：角度 + 速度 + 时序状态机，双路径（动态/静态）兼顾准确率与召回率，抗混淆、防抖；
4. **完整的报警闭环**：本地蜂鸣器 + 现场短视频取证 + MQTT 云端上报；
5. **Store-and-Forward 容灾**：SQLite 断网落盘、恢复补传，报警不丢失；
6. **工程健壮性**：优雅退出、异步日志、滚动文件、资源析构释放、编码器回退、宽高取偶等细节打磨；
7. **配置驱动**：单例 ConfigManager + 全字段默认值，参数化阈值可灵活调优；
8. **标准化交叉编译**：CMake + toolchain + sysroot，一键构建到目标板。

## 15. 未来展望

- **模型升级**：可替换为更准的 YOLOv8n-pose 变体或引入多目标跟踪（ByteTrack）区分多人场景；
